# Encrypt Config.toml with SOPS

Keep the `Config.toml` of your WSO2 Integrator (Ballerina) project encrypted in Git using [SOPS](https://github.com/getsops/sops), and let the Ballerina code-to-cloud (c2c) extension turn it into a Kubernetes `Secret` at build time.

## Overview

`Config.toml` holds the values of `configurable` variables — often API keys, database passwords, and tokens — so it must never be committed in plaintext. With SOPS you commit an **encrypted** copy (`Config.toml.enc`) instead, and decrypt it only at build or deploy time.

The workflow looks like this:

1. Secrets live in `Config.toml` locally (gitignored).
2. SOPS encrypts it with an [age](https://github.com/FiloSottile/age) key into `Config.toml.enc`, which is safe to commit.
3. Before building, SOPS decrypts `Config.toml.enc` back to `Config.toml`.
4. `bal build` with the c2c extension packages `Config.toml` into a Kubernetes `Secret`, mounts it into the pod, and points `BAL_CONFIG_FILES` at it — no hand-written Kubernetes YAML needed.

This tutorial uses Ballerina **2201.13.4** (Swan Lake Update 13).

## Prerequisites

- [Ballerina 2201.13.4](https://ballerina.io/downloads/)
- [SOPS](https://github.com/getsops/sops/releases) (3.8 or later)
- [age](https://github.com/FiloSottile/age#installation) (`age-keygen`)
- Docker (c2c uses it to build the container image)
- `kubectl` with access to a Kubernetes cluster (for deployment)

## Step 1: Create the sample integration

Create a new package:

```bash
bal new greeter
cd greeter
```

Replace `main.bal` with a small HTTP service that reads its secrets from `configurable` variables:

```ballerina
import ballerina/http;
import ballerina/log;

// Sensitive values supplied via Config.toml (kept encrypted with SOPS in Git).
configurable string apiKey = ?;
configurable string dbPassword = ?;

// Non-sensitive values can have defaults.
configurable int servicePort = 9090;

service / on new http:Listener(servicePort) {

    resource function get greeting(@http:Header {name: "x-api-key"} string key)
            returns string|http:Unauthorized {
        if key != apiKey {
            return http:UNAUTHORIZED;
        }
        log:printInfo("Authorized request served",
                dbPasswordLength = dbPassword.length());
        return "Hello from a SOPS-secured WSO2 Integrator service!";
    }

    resource function get healthz() returns string {
        return "OK";
    }
}
```

The `= ?` syntax makes `apiKey` and `dbPassword` **required** — the program refuses to start without them, so a missing configuration fails fast instead of running with an empty secret.

## Step 2: Enable Kubernetes artifact generation

Enable the c2c extension in `Ballerina.toml`:

```toml
[package]
org = "wso2"
name = "greeter"
version = "0.1.0"
distribution = "2201.13.4"

[build-options]
observabilityIncluded = true
cloud = "k8s"
```

Then create a `Cloud.toml` at the package root. The key entry is `[[cloud.config.secrets]]`, which tells c2c to package `Config.toml` as a Kubernetes `Secret` (rather than a ConfigMap):

```toml
[container.image]
repository = "wso2"   # your registry namespace, e.g. registry.example.com/team
name = "greeter"
tag = "0.1.0"

# Mount Config.toml as a Kubernetes Secret (not a ConfigMap).
[[cloud.config.secrets]]
file = "Config.toml"

[cloud.deployment]
min_memory = "256Mi"
max_memory = "512Mi"
min_cpu = "200m"
max_cpu = "500m"

[cloud.deployment.probes.readiness]
port = 9090
path = "/healthz"

[cloud.deployment.probes.liveness]
port = 9090
path = "/healthz"
```

## Step 3: Create the plaintext Config.toml

```toml
# Config.toml — NEVER committed; only the encrypted copy goes to Git.
apiKey = "sk-live-abc123-do-not-share"
dbPassword = "s3cur3-p@ssw0rd"
servicePort = 9090
```

The default `.gitignore` generated by `bal new` already excludes `Config.toml`. You will also generate an age key in the next step, so extend it:

```
# .gitignore additions
age.key
```

## Step 4: Generate an age key pair

SOPS supports several key backends (age, PGP, AWS KMS, GCP KMS, Azure Key Vault, HashiCorp Vault). This tutorial uses age because it needs no external infrastructure.

```bash
age-keygen -o age.key
```

```
Public key: age1yekajhvj4f47esgfynwra75gk69zt446ejgsgzjr2st3l3z0fpgqhj7khx
```

- The **public key** (`age1...`) encrypts. It is not sensitive — commit it in `.sops.yaml`.
- The **private key** (inside `age.key`) decrypts. Store it in a password manager or secrets vault, never in Git.

Create a `.sops.yaml` at the package root so SOPS automatically picks the right key for `Config.toml`:

```yaml
creation_rules:
  - path_regex: Config\.toml$
    age: age1yekajhvj4f47esgfynwra75gk69zt446ejgsgzjr2st3l3z0fpgqhj7khx
```

To let multiple teammates decrypt, list several recipients: `age: age1aaa...,age1bbb...`.

## Step 5: Encrypt Config.toml

```bash
sops --encrypt Config.toml > Config.toml.enc
```

> **Note:** SOPS has no native TOML store, so it treats `.toml` files as binary and wraps the whole file in a JSON envelope. The result is fully encrypted and safe to commit:

```json
{
    "data": "ENC[AES256_GCM,data:64gEjH6cVzP02mly...,type:str]",
    "sops": {
        "age": [ ... ],
        "lastmodified": "...",
        "mac": "ENC[AES256_GCM,...]"
    }
}
```

Commit the encrypted file and the SOPS configuration:

```bash
git add Config.toml.enc .sops.yaml .gitignore
git commit -m "Add SOPS-encrypted configuration"
```

## Step 6: Decrypt and build

Whenever you (or a pipeline) need to build, decrypt first — c2c reads `Config.toml` at **build time** to generate the Kubernetes `Secret`:

```bash
export SOPS_AGE_KEY_FILE=./age.key
sops --decrypt Config.toml.enc > Config.toml

bal build
```

The build compiles the package, builds the `wso2/greeter:0.1.0` Docker image, and generates the Kubernetes artifacts:

```
Generating artifacts

        @kubernetes:Service
        @kubernetes:Secret
        @kubernetes:Deployment
        @kubernetes:HPA
        @kubernetes:Docker

Execute the below command to deploy the Kubernetes artifacts:
        kubectl apply -f ./target/kubernetes/greeter
```

## Step 7: Inspect the generated artifacts

Open `target/kubernetes/greeter/greeter.yaml`. The `Config.toml` content is embedded as a `Secret` and mounted into the pod, with `BAL_CONFIG_FILES` already wired up:

```yaml
apiVersion: "v1"
kind: "Secret"
metadata:
  name: "config-secret"
data:
  Config.toml: "YXBpS2V5ID0gInNrLWxpdmUt..."   # base64 of the decrypted Config.toml
---
apiVersion: "apps/v1"
kind: "Deployment"
spec:
  template:
    spec:
      containers:
      - env:
        - name: "BAL_CONFIG_FILES"
          value: "/home/ballerina/secrets/Config.toml:"
        image: "wso2/greeter:0.1.0"
        volumeMounts:
        - mountPath: "/home/ballerina/secrets/"
          name: "config-secret-volume"
          readOnly: true
      volumes:
      - name: "config-secret-volume"
        secret:
          secretName: "config-secret"
```

> **Warning:** After the build, `Config.toml` (plaintext) and `target/kubernetes/greeter/greeter.yaml` (base64-encoded plaintext) exist on disk. Both are covered by `.gitignore` (`Config.toml`, `target/`) — never commit or publish them. Delete `Config.toml` after the build if you don't need it locally.

## Step 8: Deploy and test

Push the image to a registry your cluster can pull from, then apply the generated artifacts:

```bash
docker push wso2/greeter:0.1.0
kubectl apply -f target/kubernetes/greeter
```

Test the service:

```bash
kubectl port-forward svc/greeter-svc 9090:9090 &

curl http://localhost:9090/healthz
# OK

curl -H "x-api-key: sk-live-abc123-do-not-share" http://localhost:9090/greeting
# Hello from a SOPS-secured WSO2 Integrator service!
```

A request with a wrong key returns `401 Unauthorized` — the secret came from the mounted `Secret`, decrypted from Git only at build time.

## Rotating secrets

1. Decrypt: `sops --decrypt Config.toml.enc > Config.toml`
2. Edit the value in `Config.toml`
3. Re-encrypt: `sops --encrypt Config.toml > Config.toml.enc`
4. Commit `Config.toml.enc`, rebuild, and redeploy

To add or remove age recipients, update `.sops.yaml` and run `sops updatekeys Config.toml.enc`.

## Best practices

1. **Commit only `Config.toml.enc` and `.sops.yaml`** — keep `Config.toml`, `age.key`, and `target/` gitignored.
2. **Protect the age private key** like any production credential — vault or password manager, one key per environment.
3. **Decrypt as late as possible** — ideally only inside the build/deploy step.
4. **Prefer a KMS backend** (AWS KMS, GCP KMS, Azure Key Vault) over raw age keys in production, so decryption is controlled by IAM instead of a file.
